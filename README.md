# among-us-clone

Браузерная 2D-игра в стиле Among Us (до 5 игроков). Phaser 3 + Node.js + Socket.IO.

**Сейчас готово (этап 1):** создание лобби, вход по коду, до 5 игроков, у каждого свой цвет, все бегают по комнате ожидания и видят друг друга, хост запускает игру.

## Запуск

Нужен **Node.js 20+** (проверить: `node -v`).

```bash
npm install     # один раз, ставит зависимости для клиента и сервера
npm run dev     # запускает сервер (порт 3000) и клиент (порт 5173)
```

Открой http://localhost:5173 в двух вкладках: в одной создай лобби, в другой войди по коду.

### Играть с разных ноутбуков (одна Wi-Fi сеть)
1. Один человек запускает `npm run dev`.
2. В терминале Vite покажет адрес вида `Network: http://192.168.x.x:5173`.
3. Остальные открывают этот адрес у себя в браузере. Клиент сам подключится к серверу на том же компьютере.
4. Если не подключается, проверь брандмауэр Windows: разреши Node.js доступ к частным сетям.

### Тесты
```bash
npm test          # юнит-тесты логики комнат (server/test)
npm run test:e2e  # сквозная проверка ботами (сначала запусти сервер)
```

Для теста старта в одиночку запусти сервер с `MIN_PLAYERS=1`.

## Структура

```
client/                 Phaser + Vite
  src/main.js           конфиг игры
  src/net/socket.js     подключение к серверу (вся сеть только здесь)
  src/scenes/MenuScene.js   меню: ник, «Создать», «Войти по коду»
  src/scenes/LobbyScene.js  комната ожидания: движение, игроки, панель
  src/game/crewSprite.js    временный персонаж-заглушка и анимации
  public/assets/        сюда кладём спрайты
server/
  src/index.js          Express + Socket.IO (приём и рассылка событий)
  src/rooms.js          логика комнат, без сети, легко тестировать
  test/rooms.test.js    тесты
shared/events.js        контракт событий и общие константы
scripts/smoke-test.js   сквозной тест ботами
```

## Контракт событий (`shared/events.js`)

| Направление | Событие | Данные |
|---|---|---|
| клиент → сервер | `create_room` | `{ name }` |
| клиент → сервер | `join_room` | `{ code, name }` |
| клиент → сервер | `leave_room` | — |
| клиент → сервер | `start_game` | — (только хост) |
| клиент → сервер | `move` | `{ x, y }` |
| сервер → клиент | `room_joined` | `{ code, you }` |
| сервер → клиент | `room_update` | `{ code, hostId, state, minPlayers, players: [{ id, name, color, x, y }] }` |
| сервер → клиент | `error_msg` | `{ message }` |
| сервер → клиент | `game_started` | `{ code }` |
| сервер → клиент | `player_moved` | `{ id, x, y }` |

**Правило:** новое событие сначала добавляем в `shared/events.js`, а строки событий руками в коде не пишем.

## Кто за что отвечает

| Зона | Файлы | Что делать дальше |
|---|---|---|
| **Сервер** (Team Lead) | `server/src/*`, `shared/events.js` | Роли (предатель/экипаж), состояния игры, валидация |
| **Клиент: UI и сеть** | `MenuScene.js`, панель в `LobbyScene.js`, `net/socket.js`, `style.css` | Экраны, ошибки, переподключение |
| **Геймплей** | движение и синхронизация в `LobbyScene.js` | Карта игры, коллизии со стенами, камера |
| **Арт и тесты** | `client/public/assets/`, `crewSprite.js` | Спрайтшит `crew.png` (32×32, idle 2 + walk 4 кадра, **белый**), фон, ручные тест-кейсы |

## Как работаем с Git

1. Никогда не коммитим прямо в `main`.
2. На каждую задачу своя ветка: `git checkout -b server-roles`.
3. Готово? Делаем `git push -u origin server-roles`, на GitHub открываем **Pull Request** в `main`.
4. Team Lead проверяет и сливает PR. Перед новой задачей делаем `git checkout main && git pull`.
